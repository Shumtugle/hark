# Hark

A player for long recordings from a single folder on Android. Two-hour lectures, audiobooks, recorded talks — it opens a folder, not a library, and it remembers where you stopped in every file.

Every line of code, every pixel of layout, every byte of logic was generated by AI (**Claude Opus 5**) through plain conversation. Not a single line was written by a human hand. No Android Studio, no Gradle, no dependencies: `javac` against a platform stub, `dx`, `aapt`, `apksigner`. The interface is built in code — there is not one layout XML in the project.

**Package:** `io.github.shumtugle.hark` · **Version:** 2.9.7 · **Site:** [shumtugle.github.io/hark](https://shumtugle.github.io/hark/)

## The rules

- **A folder, not a library.** One query, no storage scan, no database, no index. Files appear as they lie on disk.
- **Position over everything.** The place inside each file is kept separately, keyed by document id. Resuming rewinds five seconds so you hear the end of the previous sentence, not the middle of a word.
- **Everything audible by default.** One chip narrows the list to the MP4 family — m4a, m4b, mp4, aac — and the choice is remembered. MP4 files always sort first. When a filter hides every file, the empty screen says so and offers to lift it.
- **The filter is remembered.** It returns as you left it, and that can be switched off in settings.
- **Rewind on resume.** Speech breaks mid-sentence when you pause, so resuming exactly where you stopped is useless. Playback steps back three and a half seconds by default, adjustable or off.
- **Nothing finishes itself.** No auto-resume when headphones return, no playlists, no shuffle, no equaliser, no cover art.

## How it thinks

**A two-hour file breaks the scrub bar.** One pixel is about seven seconds, so precise seeking by drag is impossible. Three levels of access instead: fifteen- and thirty-second buttons, coarse dragging across the whole panel height, and exact time entry on a long press of the digits.

**Length is fetched lazily.** Reading metadata for three hundred files at once freezes the screen for seconds. Each duration is read as its row is drawn and cached, so sorting by length settles a moment after the folder opens.

**Both extension and MIME are checked.** Some firmware returns `application/octet-stream` instead of an honest audio type; a filter trusting one signal alone would swallow half the folder.

**Android does not pause for headphones.** Pulling the jack moves the sound to the speaker — the app must listen for `ACTION_AUDIO_BECOMING_NOISY` and pause itself. Resuming is manual by design.

**Speed can start the sound by itself.** On some devices, setting playback speed on a paused player silently resumes it. The state is recorded before the change and restored after.

**A broken file does not stop the queue.** If a file is corrupt or vanished, playback moves to the next one instead of standing still, and the incident goes into the inquest log.

**Files disappear.** The "Continue" row verifies the file still exists before drawing itself. A file deleted during playback plays to the end anyway — the descriptor is still open.

**Fifteen languages**, with right-to-left layout for Arabic, Hebrew and Urdu. By default the app follows the system language and falls back to English.

## Headphones

The header and the widget show a headset mark whenever sound leaves for one, amber for Bluetooth and grey for a cable, with the charge beside it when the hardware will say. Some firmware and some headsets never expose the level to an ordinary app; the indicator then disappears entirely rather than showing an empty frame that promises data which is not coming.

## On the home screen

A widget shows the file, folder, position bar, times, five buttons and cover art, with speed cycling on a tap. Artwork embedded in the file comes first, then an image in the same folder — the path that matters for a book cut into chapters, which carries no tags but keeps its cover as a file. Its buttons work even after Android evicts the app from memory: the player raises itself, reads the last file and position from storage, and continues from the same second. Fill and frame are separate layers: the fill dials down through five steps to nothing, leaving a thin outline with the wallpaper behind it, while the frame always stays — without it the contents read as scattered rather than as one object.

## Navigation

One line holds what is used constantly: back arrow, folder name, the MP4 filter, and a star for bookmarks. Everything occasional lives behind the logo — sorting, history, folder picker, settings, help.

**Bookmarks** keep up to twenty favourite folders, each remembering the volume it sits on. A folder on a memory card is bookmarked alongside internal storage, and Hark switches trees when you jump there; a bookmark whose volume is no longer permitted is drawn in brick with a dash.

## The inquest

A long press on the filter chip opens a report: what MIME the firmware gave each file, whether the folder permission is alive, whether audio focus was granted, whether the headphone notice fired. Sections separated by air, log newest at the bottom, and a filter field that selects lines rather than highlighting them — the technique is borrowed from [Jot](https://github.com/Shumtugle/jot).

The log dies with the app, but the stack of the last crash is written to a file and waits in the same report on the next launch.

## Permissions

No internet, no location, no storage scan, no accounts, no ads, no analytics. Access to one folder, granted by you once through the system picker. The rest is the mechanics of sound: a foreground service, its notification, and a wake lock while playing.

## Building

```
apt-get install -y apktool aapt zipalign apksigner default-jdk dalvik-exchange
./build.sh 2.9.7
```

An `android.jar` stub for API 33 is required; `dx` ships as `dalvik-exchange` on Debian and Ubuntu.

One scar worth recording: the first build crashed on launch. `dx` is old enough to leave `invoke-custom` in the bytecode, asking the runtime for `LambdaMetafactory` — a class Android does not provide. Modern `d8` always desugars lambdas for exactly this reason. All forty-seven were rewritten as anonymous classes.

## A note on the source

The published sources carry no comments. The working copy kept alongside them is commented throughout, in the language the project was built in; the two are otherwise identical, and both compile with the same `build.sh`.
